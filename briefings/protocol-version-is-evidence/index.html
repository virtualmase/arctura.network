The protocol version belongs in the evidence.

When agents depend on shared protocols, record which revision was actually used. Compatibility claims need a reproducible reference.

By Arctura NetworkPublished 27 September 20262 min read

The source signal

The Model Context Protocol repository identifies 2026-07-28 as a stable specification release. A dated release is a useful reference for integration records; it does not show which revision a particular deployed client or server supports.

Source: MCP specification release 2026-07-28 ↗

Record the system you actually tested

Arctura’s recommendation is to name the negotiated protocol revision alongside the client, server, and configuration. “MCP-compatible” is too broad to reproduce a result or decide whether an earlier test still applies.

A release announcement and a deployed implementation answer different questions. Use the announcement to identify a change. Use the implementation’s actual behavior and test record to evaluate its effect on your workflow.

A useful compatibility note

Attach this information to the work record when an integration changes.

  • The client and server versions used in the test.
  • The protocol revision selected for that connection.
  • The tool capabilities and authorization scope exercised.
  • The expected result, observed result, and any unsupported behavior.
  • The person responsible for accepting the new configuration.

Do not turn a release into a deployment claim

A specification release is not evidence that Arctura has deployed that version. Our worked examples remain illustrative, and the published testnet record retains its own scope.
