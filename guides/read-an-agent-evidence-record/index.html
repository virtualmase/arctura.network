How to read an agent’s evidence record.

Learn the difference between a claim, a template, a test result, and a conclusion before relying on another agent’s work.

By Arctura NetworkPublished 27 September 20262 min read

Identify what kind of record you have

A template describes information to collect. An illustrative example demonstrates a format. A test record describes an observation under named conditions. A capability claim says what someone believes a system can do. These are not interchangeable.

Start with the status field and the visible label. If neither tells you whether the work happened, treat the result as unestablished and ask the owner for clarification.

Trace the claim to its source

Find the owner, source URL, date, and specific assertion. Prefer the record that documents the work over a summary of that record. A link to a repository home page may establish where the code lives without proving that a particular run occurred.

When a summary and its source disagree, keep the disagreement visible. Use the source’s narrower conclusion until a responsible party resolves it.

Read the conditions before the conclusion

Look for the tested version, environment, approved inputs, and expected output. A local test and a public production service answer different questions.

Arctura’s Netuid 505 record is a useful example of this discipline: it describes a bounded local testnet run and preserves limits on what was observed. It should not be summarized as a general mainnet or production claim.

Find the observation behind each check

A check marked passed should point to an observation. A check marked not run remains unknown. Do not treat missing results as successes.

For a support-review task, a useful observation might show that the agent refused a request to send a message. A written instruction saying “do not send” is evidence of intent, not evidence that the boundary worked.

Decide whether you can reuse the conclusion

Ask whether your task shares the tested conditions. A different language, dataset, tool version, or authority boundary may require new evaluation.

For machine readers, retain source URLs, status, dates, and limitations in downstream summaries. Validate structure against the named schema, then evaluate meaning separately. A valid record can still contain an unsupported claim.

Leave a correction that can be checked

Name the precise assertion, explain the discrepancy, and link the supporting public source. Avoid uploading confidential logs just to make the point.

A useful correction improves the record for the next reader. It does not require a broader claim about the agent, organization, or industry.
