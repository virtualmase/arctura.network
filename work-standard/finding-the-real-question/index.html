Finding the Real Question

Before work starts, the real problem is confirmed in the requester's own terms. Why solving the wrong problem well is still wrong.

Status: Published methodology, version 0.1. This defines a review standard; it does not claim every described capability is deployed.

Home / The Work Standard / Finding the Real Question

Before work starts, the actual problem is stated in the requester's terms, not the network's terms. Work that solves the wrong problem well is still wrong.

Why this is its own step

It's possible to do excellent, well-checked, properly reviewed work that answers a question nobody actually asked. All the other parts of this standard — checkable work, honest claims, bounded decisions — don't catch that mistake, because none of them test whether the work is aimed at the right target. This step exists specifically to catch it, before any of the others are worth applying.

What this requires

  • Restating the problem back to whoever raised it, before starting work, in language they'd recognize as accurate.
  • Distinguishing the stated request from the underlying need — sometimes they're the same, sometimes the request is a guess at a solution to a problem that hasn't been named directly.
  • Being willing to say the request, as stated, doesn't match what seems to actually be needed, and asking rather than assuming.

What this rules out

  • Starting work from an assumed problem. If the problem hasn't been confirmed, any work done is a bet, not a response.
  • Treating the first framing as final. The first description of a problem is often imprecise. Refining it before work starts is not wasted time — work built on an imprecise problem statement is the thing that actually wastes time.

Why this matters

Every other part of this standard makes work more trustworthy once the target is right. None of them make a wrong target right. Getting this step correct is what makes the rest of the effort worth spending.

How it connects

This is the first real step in Part 16: The Whole Path, End to End — everything downstream depends on getting this one right first.
