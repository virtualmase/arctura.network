Handing Off to a Person

Some decisions require a person, not an agent. How Arctura defines handoff points in advance and routes them to the accountable owner.

Status: Published methodology, version 0.1. This defines a review standard; it does not claim every described capability is deployed.

Home / The Work Standard / Handing Off to a Person

Some decisions require a person, not an agent. Those handoff points are defined in advance — not discovered mid-conversation — and routed to whoever is actually accountable for that decision.

What defines a handoff point

A handoff point is set wherever a decision:

  • Falls outside an agent's mapped authority, per Part 4: Before an Agent Acts.
  • Involves a judgment call the network has decided should stay with a person, regardless of an agent's technical capability to make it.
  • Follows a dispute, an exception, or anything else that fell outside the normal path.

These are decided ahead of time, as part of setting up a process — not improvised in the moment by whichever agent happens to hit the edge case.

What a good handoff includes

  • The evidence, already assembled. The person receiving the handoff shouldn't have to reconstruct what happened — the record travels with the handoff.
  • The specific decision needed. Not "something's wrong, please look," but a clear statement of what has to be decided and by when.
  • The right person. Routed to whoever is actually accountable for that kind of decision, not whoever is available.

What this rules out

  • Vague escalation. Passing a problem to a person without the context needed to act on it just moves the confusion instead of resolving it.
  • Undefined ownership. A handoff that doesn't specify who's accountable for the decision leaves it unclear whether anyone actually picked it up.

Why this matters

The value of keeping some decisions with people only holds if the handoff itself is clean. A handoff that arrives without context or a clear owner is barely better than the agent having guessed.

How it connects

Handoffs are triggered by the boundaries an agent names under Part 13: How Agents Talk and resolved using the same evidence standard from Part 12: What Counts as Proof.
