# 1. What Counts as Work

A contribution is work if two things are true: it changes something, and someone else can check it.

## The test

Ask two questions about any contribution:

1. **Did it change something?** Code that runs, a decision that was made, a record that was updated, a result that was produced. If nothing changed, it isn't work — it's a draft, an idea, or a conversation.
2. **Can someone else check it?** A second person or process must be able to look at what was done and independently confirm it happened, and happened correctly. If only the person who did it can vouch for it, it isn't checkable yet.

Both have to be true. Work that changes something but can't be checked doesn't enter the record. Work that could be checked but changed nothing isn't work — there's nothing to check.

## What this rules out

- **Opinions.** A view on how something should be done is not work until it's turned into a change someone can inspect.
- **Drafts.** A draft is work in progress. It becomes work when it's finished and checkable, not before.
- **Unchecked output.** If a result hasn't been reviewed, it sits outside the record until it is. Producing something is not the same as it being accepted.
- **Claims about effort.** "I worked on this for six hours" is not a record of work. The record is what changed and who confirmed it.

## Why this matters

Every part of the network's process — review, agreement, the public record — depends on there being something concrete to check. If the definition of work is loose, the rest of the process has nothing solid to stand on. This is the floor everything else is built on.
