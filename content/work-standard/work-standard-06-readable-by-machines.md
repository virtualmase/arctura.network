# 6. Readable by Machines

Records are structured so software can find and parse them correctly. This makes the record easier to find. It does not promise ranking, placement, or preferential retrieval anywhere.

## What "readable by machines" actually means

- Consistent structure across pages, so a script or a crawler can extract the same kind of information from the same kind of page, every time.
- Plain, literal language over stylized or ambiguous phrasing, so meaning doesn't depend on context a machine doesn't have.
- Explicit dates, sources, and identifiers attached to claims — not implied by surrounding text.
- Discovery files and structured data that describe what a page actually contains, accurately, without exaggeration.

## What this rules out

- **Claiming this improves search ranking.** It doesn't, on its own. Structure makes content easier to parse correctly. Whether anything ranks or gets retrieved is decided elsewhere, by systems Arctura doesn't control.
- **Gaming structured data.** Marking something as one type of content to get better treatment when it's actually another type. If the markup doesn't match the content, it comes out.
- **Writing for machines instead of people.** Machine-readability is a constraint on top of clarity, not a replacement for it. If a page is confusing to a person, restructuring it for a crawler doesn't fix the actual problem.

## Why this matters

More and more of what happens on the network — review, verification, discovery — is done partly by software, not just people. If the record isn't structured in a way software can reliably parse, that software either fails or fills the gap with a guess. Neither is acceptable for a public record.

## How it connects

This is the same discipline applied to [Documentation](/documentation/netuid-505/) and every page describing how the network's implementation works — structure that holds up whether the reader is a person or a program.
